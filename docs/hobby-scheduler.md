# Запуск на Vercel Hobby без встроенного минутного Cron

В `vercel.json` нет поля `crons`. Это устраняет отказ Hobby из-за расписания `* * * * *`. Защищённый обработчик `/api/cron` сохранён; без внешнего планировщика сообщения останутся в очереди. Таблицы/миграции для этого изменения не нужны.

## 1. Дождитесь новой публикации

После появления нового коммита в main Vercel должен автоматически начать deploy. Откройте последнее развёртывание и проверьте его SHA: повтор старого deployment не обязан взять новую конфигурацию. Если сборка успешна, статус Ready. Другая ошибка сборки требует отдельного исправления.

В проекте Vercel задайте Production-переменные DATABASE_URL, DIRECT_URL, BOT_TOKEN, NEXT_PUBLIC_BOT_USERNAME, OWNER_TELEGRAM_IDS, AUTH_SECRET, WEBHOOK_SECRET и CRON_SECRET. Токены, URL с паролями и три секрета — тип Secret; имя бота — Config. Изменения переменных требуют нового deployment.

Получите постоянный production-домен через Domains или Visit. APP_URL — HTTPS-адрес самого приложения, без пути и завершающего слеша. Сохраните его в Vercel и в GitHub Repository secrets. Если показан только адрес неудавшейся/preview-публикации, сначала завершите production deploy. Preview-защита не должна блокировать публичные маршруты Telegram и планировщика; используйте поддерживаемые настройки защиты Vercel.

## 2. Подключите Telegram

Проверьте GET /api/health: ожидается status=ok. В BotFather настройте /setdomain для входа. В GitHub Actions запустите НОВЫЙ Production setup из main с операцией webhook. Нужны GitHub Secrets BOT_TOKEN, WEBHOOK_SECRET и APP_URL. WEBHOOK_SECRET должен совпадать с Vercel. Успех регистрации не подтверждает обработку очереди.

## 3. Создайте задание во внешнем планировщике

Например, используйте https://cron-job.org. У сервиса есть минутное расписание и поддержка пользовательских HTTP-заголовков; доступность и ограничения текущего тарифа проверяйте в его интерфейсе. Регистрацию и передачу секрета выполняет владелец через защищённую форму сервиса, без публикации значений в чат или GitHub.

1. Создайте аккаунт и подтвердите email, если потребуется.
2. В панели откройте Cronjobs → Create cronjob (названия могут отличаться).
3. Название: Maksim queue.
4. URL: https://ВАШ-PRODUCTION-ДОМЕН/api/cron. Замените домен на настоящий адрес приложения.
5. Расписание: каждая минута. Если используется cron-выражение: * * * * *.
6. Метод запроса: GET. Включите задание.
7. В расширенных параметрах добавьте HTTP-заголовок:
   - имя: Authorization
   - значение: Bearer ВАШ_CRON_SECRET
8. После слова Bearer нужен ровно один пробел, затем настоящее значение переменной CRON_SECRET из Vercel. Не вставляйте название переменной вместо её значения. Не используйте BOT_TOKEN и не помещайте секрет в URL.
9. Сохраните и выполните Test run / Run now, если такой пункт есть.
10. Ожидается HTTP 200 и {"accepted":true}. {"busy":true} тоже HTTP 200: предыдущая обработка ещё не завершилась.

Endpoint использует Next.js after(): планировщик не ждёт завершения запросов Telegram. Работа продолжается средствами Vercel в рамках maxDuration=60. Не используйте отдельный setTimeout или fire-and-forget процесс вместо after(). Во время холодного запуска подключение к Neon перед ответом может занять дополнительное время.

## 4. Проверьте реальную обработку

1. Отправьте боту /start.
2. Дождитесь ближайшего запуска (обычно до минуты, при накопившейся очереди дольше).
3. В админке владелец открывает Настройки и смотрит системную запись schedulerStatus. Не пытайтесь редактировать её: она обновляется автоматически.
4. status=ok, свежий completedAt и done показывают завершившийся пакет. completed_with_failures означает, что часть задач не выполнилась; проверьте Очередь задач. status=error означает сбой обслуживания или БД.
5. Убедитесь, что пользователь действительно получил ответ. Зелёный HTTP-тест планировщика означает приём запуска, а не доставку сообщений.
6. Включите оповещения планировщика об HTTP-ошибках; дополнительно следите за очередью и свежестью schedulerStatus, поскольку фоновая ошибка возможна после ответа HTTP 200.

## Диагностика

- 401: отсутствует/неверен Authorization, секрет не совпадает или не применён новый deploy.
- 404: неверный адрес/путь либо приложение ещё не опубликовано.
- Перенаправление на вход Vercel или HTML вместо JSON: проверьте production-домен и Deployment Protection.
- 5xx/timeout: проверьте Vercel Logs и подключение Neon. Не отключайте проверку авторизации ради устранения ошибки.
- accepted=true, но бот молчит: проверьте BOT_TOKEN, webhook, Очередь задач и schedulerStatus.
- busy=true единично: предыдущий запуск активен. Постоянно устаревший status: проверьте зависшие/прерываемые вызовы.

При ротации CRON_SECRET обновите и Vercel (с новым deployment), и заголовок внешнего задания. При смене домена обновите URL задания и webhook. Ограничения использования Hobby, объёма serverless-вычислений и внешнего сервиса остаются применимыми; этот вариант предназначен прежде всего для запуска и проверки небольшой нагрузки.
