# Вход в админку через своего бота

На /login основной способ — «Войти через бота». Он использует работающий webhook и очередь; служебное уведомление Telegram Login с подтверждением номера телефона не требуется. Классический Telegram Login сохранён в раскрываемом разделе «Другой способ».

## Пользовательский сценарий

1. Откройте https://maksim-seven.vercel.app/login (или актуальный production-домен).
2. Нажмите «Войти через бота».
3. Нажмите «Открыть бота и подтвердить вход»; оставьте страницу сайта открытой.
4. В Telegram нажмите «Запустить / Start», если предлагается.
5. В своём боте проверьте домен и нажмите «Подтвердить вход».
6. Вернитесь в тот же браузер. Страница автоматически откроет /admin.

При минутном внешнем планировщике сообщение бота и обработка подтверждения могут занять по минуте. Ссылка действует пять минут. Если она истекла, создайте новую на сайте. Не пересылайте ссылку другим людям и не подтверждайте запросы, если сами не начали вход в своём браузере.

## Настройки

Используются существующие APP_URL, AUTH_SECRET (32+ символа), BOT_TOKEN, NEXT_PUBLIC_BOT_USERNAME и OWNER_TELEGRAM_IDS. Для делегированных администраторов — включённая запись Admin. Требуются работающие Telegram webhook и внешний планировщик. Новых секретов, таблиц и миграций не нужно: короткоживущие записи хранятся в Setting и скрыты из редактора настроек. Не сбрасывайте базу для подключения этого способа.

/setdomain в BotFather нужен для классического Telegram Login; бот-вход подтверждается через API-обновления Telegram и не использует телефонный login widget.

## Защита

- Случайный идентификатор заявки помещается в Telegram deep link; отдельный секрет браузера туда не передаётся.
- Browser binding хранится в HttpOnly, SameSite=Strict cookie (Secure в production), подписан AUTH_SECRET. В БД хранится только хеш секрета браузера.
- Создание заявки требует точного совпадения Origin с адресом, на котором сервер обслуживает приложение, APP_URL или серверным адресом Vercel. Заголовки с чужим Origin и межсайтовые запросы отклоняются. Если браузер удалил Origin, проверяется точный адрес в специальном заголовке клиента или Referer; произвольные домены и X-Forwarded-Host не принимаются. APP_URL по-прежнему рекомендуется задавать равным основному production-адресу; публичное создание ограничено 20 новыми заявками в минуту для приложения. Повторный запрос из того же браузера переиспользует действующую заявку.
- Бот проверяет владельца/администратора по Telegram ID из доверенного webhook. Нужна явная кнопка подтверждения; /start сам по себе вход не разрешает.
- При получении сессии роль проверяется повторно. Одобрение и однократное получение сессии выполняются транзакционно. Другой браузер с одним идентификатором ссылки войти не сможет.
- Сессия подписывается существующим механизмом и действует восемь часов. Сервер продолжает проверять актуальность роли при каждом обращении к админке.
- Смена AUTH_SECRET делает ожидающие cookie недействительными. Истёкшие заявки удаляются при создании новых; действующие заявки и счётчик не отображаются в настройках.
- Подтверждения и входы записываются в AuditLog без секретов браузера.

## Диагностика

Нет ответа бота: проверьте cron-job.org, /api/health и operation diagnostics. «Вход доступен только владельцу…»: проверьте OWNER_TELEGRAM_IDS в Vercel Production, выбранный аккаунт Telegram и свежесть deployment. «Ссылка истекла»: начните вход заново на сайте. Сайт не переходит в админку: вернитесь в исходный браузер, проверьте cookies и успешность запросов /api/auth/bot; не показывайте значения cookie в скриншотах. После отзыва роли вход не выдаётся даже по ранее одобренной ссылке.

## Проверка исправления адреса запроса

Локально пройдены 64 Vitest-теста и 13 тестов настройки webhook/диагностики, production-сборка с проверкой Prisma WASM. В Chromium проверены два полных входа при устаревшем APP_URL: обычный запрос и запрос без Origin/Referer. В обоих случаях проверены домен заявки, привязка cookie, получение сессии после тестового подтверждения, открытие админки и выход. Telegram-подтверждение в браузерной проверке моделируется доверенным серверным вызовом; реальный вход нужно повторить после публикации на Vercel.
