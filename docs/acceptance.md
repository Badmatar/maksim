# Состояние реализации и приёмки

Это реализованный исходный MVP и локальные проверки, **не акт приёмки production**. Бот, Neon и Vercel не подключены: учётные данные и реальные материалы отсутствуют. Автотесты используют настоящий локальный PostgreSQL и имитацию Telegram API.

| Пункт ТЗ | Что реализовано / способ проверки |
| --- | --- |

| Аналитика | Источники, бесплатные практики, покупатели/конверсия, повторные покупатели, выручка по валютам/продуктам, доставленные рассылки |

## Что ещё нужно до production

- Собственный бот, OWNER_TELEGRAM_IDS, реальные ключи/секреты, домен, Neon и проект Vercel.
- Разрешить `binaries.prisma.sh` и проверить стандартный `prisma migrate deploy` на staging. Локальные тесты используют SQL из той же Prisma-миграции; production deploy в этой среде не проверен.
- Настроить внешний минутный планировщик для Vercel Hobby по docs/hobby-scheduler.md, права бота в закрытой группе и Telegram Login domain.
- Загрузить реальные аудио, тексты, цены, реквизиты и расписание; сейчас база не наполнена вымышленными материалами.
- Проверить совместимость ручной оплаты цифровых товаров с действующими правилами Telegram/Stars; подключить соответствующий адаптер до таких продаж.
- Подключить Sentry, оповещения об ошибках очереди, Neon backup/PITR и фактически проверить восстановление.
- Утвердить политику обработки данных, сроки хранения и процедуру удаления. Автоматическая очистка/удаление и защищённое архивирование медиа не реализованы.
- Пройти полный цикл в реальном Telegram: /start → бесплатное аудио → квитанция → сверка/подтверждение → аудио/вступление → продление/истечение. Реальные банковские поступления сверяются человеком.
- Утвердить правила частичных возвратов: MVP отмечает полный возврат заказа и отзывает весь доступ к продукту.

## Проверки разработчика

Создайте отдельную PostgreSQL-базу с именем, заканчивающимся на `_test`. Примените начальный SQL через `DATABASE_URL=... npm run db:local` **только на localhost**. Укажите TEST_DATABASE_URL, затем `npm test`. Тесты очищают только выбранную disposable test-базу. Для production/Neon такой запуск запрещён.

`npm run typecheck`, `npm test`, `npm run build` — основные проверки. `npx tsx scripts/smoke.ts` при запущенном локальном production-сервере и локальных AUTH_SECRET/OWNER_TELEGRAM_IDS проверяет маршруты, права, запись контента, CSV и отзыв сессии делегированного администратора. Не запускайте smoke с реальными пользователями/данными. Временная запись контента удаляется в finally; её audit-запись сохраняется.

## Зафиксированный результат локальной проверки (26 октября 2026)

- Vitest 5: 24 теста успешно, две suite; реальные транзакции PostgreSQL, Telegram API имитируется.
- Production-сборка Next.js и проверка TypeScript: успешно.
- HTTP smoke: 29 проверок, включая защищённые API, контроль Origin, CSV, сохранение контента и отзыв прав.
- Chromium: desktop/mobile, создание/редактирование практики, отсутствие ошибок клиента и горизонтального переполнения.
- npm audit: 0 известных уязвимостей, включая dev-зависимости. Для устранения уязвимости транзитивного deepmerge-ts закреплён override 8.0.0; генерация Prisma, сборка и тесты проверены с ним.
- Локальный pg_dump/pg_restore в отдельную disposable базу: схема и выбранные количества сущностей совпали; проверочный скрипт scripts/backup-smoke.sh. Это не проверка Neon PITR и не восстановление production-данных.
- Скрипты install_script и start_skill, перечень переменных и сетевые дополнения сохранены в черновике облачной среды. Публикация среды и приложения не выполнялась.

CI workflow добавлен, но запуск в GitHub Actions пока не выполнен. Защищённый вход через настоящий Telegram Login, реальные банковские операции, production cron и Telegram-группа требуют внешних настроек и отдельной проверки.

## Обновление для Vercel Hobby

Встроенное минутное расписание Vercel удалено: Hobby отклонял deploy. Обработка очереди требует внешнего GET /api/cron каждую минуту с Authorization: Bearer CRON_SECRET. Endpoint подтверждает приём, затем использует Next.js after(); авторизация, защита от перекрывающихся запусков, статус обработки и ошибки покрыты отдельными тестами. Внешний сервис и реальная доставка Telegram должны быть проверены после публикации; удаление записи crons само по себе не запускает worker.

Проверка обновления Hobby: 31 тест приложения и 7 Node-тестов диагностики webhook прошли; production-сборка и TypeScript прошли. На локальном production-сервере с изолированной PostgreSQL проверено: запрос без секрета → 401, авторизованный запрос → HTTP 200 accepted, фоновое выполнение after() → свежий schedulerStatus=ok и освобождение lease. Реальный внешний планировщик и Vercel deploy ещё нужно проверить после публикации.
